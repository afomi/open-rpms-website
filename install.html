Install RPMS

Each release of RPMS is built from the public IHS files and published two ways. On YottaDB it is a container image you can run with no license. On IRIS it is a database you mount in your own licensed IRIS for Health. Both carry the same demo clinic: staff personas you can sign on as, and synthetic patients. This page takes you from nothing to a signed-on session and a first call from code.

Before you start

  • A machine with Docker, curl, jq and ssh, and about 20 GB free for YottaDB. IRIS needs about 25 GB more, for the downloaded databases and the copy the standup makes.
  • The YottaDB image is built for x86-64. On Apple Silicon it runs under emulation, and Docker warns that the image's platform does not match the host. That warning is expected, and the image works.
  • Releases are named like bcer-9.0-20261110-55d9e3e-ydb: the certification line, the build date, the commit, and the engine (-ydb or -iris). New releases come out often, so the commands below look up the newest one for each engine rather than naming it. Every release is listed on the releases page.
  • Each release's notes are its MANIFEST.md file, attached to the release: what it contains, layer by layer, and what each client expects.
  • The demo data is synthetic. The brokers speak plaintext, so keep their ports on your own machine or a private network, and never load real patient data into a demo instance.

The demo personas

These sign-on pairs are published with every release, on both engines. Each is a member of the demo clinic's staff, with that role's menus and keys. The verify code is the access code followed by !!.

  • PROFILE,MD, a physician: PMD123 / PMD123!!
  • PROFILE,RN, a nurse: PRN123 / PRN123!!
  • PROFILE,MA, a medical assistant: PMA123 / PMA123!!
  • PROFILE,REG, patient registration: PREG123 / PREG123!!
  • PROFILE,REGSUP, a registration supervisor: PRSUP123 / PRSUP123!!
  • PROFILE,SCHED, a scheduler: PSCH123 / PSCH123!!
  • PROFILE,BILL, a billing technician: PBIL123 / PBIL123!!. This persona works in the terminal only, so the brokers refuse it.

Option 1: YottaDB (open source)

Look up the newest YottaDB release, then pull the image and run it. It serves the CIA broker on 9100, the BMX broker on 9101 and the terminal over SSH, and it runs TaskMan. Set any password you like for the terminal's SSH account. 

TAG=$(curl -s https://api.github.com/repos/lakeraven/rpms-ops/releases \
  | jq -r '[.[] | select(.tag_name | endswith("-ydb"))][0].tag_name')
echo "$TAG"                           # the newest -ydb release
docker run -d --name rpms \
  -p 127.0.0.1:9100:9100 -p 127.0.0.1:9101:9101 -p 127.0.0.1:2222:22 \
  -e RPMS_SSH_PASSWORD='choose-one' \
  ghcr.io/lakeraven/rpms-ydb:$TAG
docker logs -f rpms                   # wait for "TaskMan live", then Ctrl-C

The first run downloads about 6 GB. Once the image is local, it reaches "TaskMan live" in under a minute.

Open the terminal, called roll and scroll. The first time, ssh asks whether to trust the container's host key: answer yes. Give the SSH password you chose, and you land at the RPMS sign-on. The codes you type are not shown. 

ssh -p 2222 rpms@127.0.0.1
ACCESS CODE: PMD123
VERIFY CODE: PMD123!!

Good morning PROFILE,MD
Site set to DEMO IHS CLINIC

Select IHS Core <TEST ACCOUNT> Option:

You are signed on as PROFILE,MD, at that persona's main menu. Type ^ at an option prompt to step back, and at the main menu it signs you off. If a persona is asked for a terminal type, press Enter to take the default. The SSH account can do nothing but reach the sign-on: no shell, no file copy, no port forwarding.

Everything you change lives inside the container. docker rm -f rpms removes it, and the next docker run starts again from the release. A new container has a new host key, so before you connect to it, forget the old one with ssh-keygen -R '[127.0.0.1]:2222'.

Option 2: IRIS for Health (bring your own license)

An IRIS release is a patched RPMS database, IRIS.DAT, plus the BMW database that the BPRM web tier reads. You bring IRIS for Health and its license key. The standup script, bin/standup.sh in the rpms-ops repository, mounts both databases in an IRIS for Health container and configures them. Name the IRIS for Health image your license covers in IRIS_IMAGE. Images from the InterSystems registry need an InterSystems login to pull. Releases are built on IRIS for Health 2022.1, which the registry no longer serves, and a release also runs on 2026.2. 

TAG=$(curl -s https://api.github.com/repos/lakeraven/rpms-ops/releases \
  | jq -r '[.[] | select(.tag_name | endswith("-iris"))][0].tag_name')
echo "$TAG"                           # the newest -iris release
URL=https://github.com/lakeraven/rpms-ops/releases/download/$TAG
for f in IRIS.DAT BMW-IRIS.DAT; do
  curl -LO "$URL/$TAG-$f.gz"
  curl -LO "$URL/$TAG-$f.sha256"
  gunzip -k "$TAG-$f.gz"
done
shasum -a 256 -c "$TAG-IRIS.DAT.sha256" "$TAG-BMW-IRIS.DAT.sha256"

git clone https://github.com/lakeraven/rpms-ops
CONTAINER=rpms-iris \
IRIS_IMAGE=containers.intersystems.com/intersystems/irishealth:<your version> \
IRIS_KEY=/path/to/iris.key \
RPMS_SSH_PASSWORD='choose-one' \
  rpms-ops/bin/standup.sh "$PWD/$TAG-IRIS.DAT"

Give the database as a full path, as $PWD does here: the script runs from its own directory, so a relative path is not found. It finds the BMW database beside it. CONTAINER names the container the script creates, and it replaces any container already using that name. Its default is rpms, the name Option 1 uses, so set it if you run both.

The script takes about five minutes. It prints BUILD-LEVEL: PASS once the instance passes its checks, then RPMS up. The terminal is SSH on port 12222, and the same demo personas sign on. 

ssh -p 12222 rpms@127.0.0.1
ACCESS CODE: PMD123
VERIFY CODE: PMD123!!

Inside the container the CIA broker listens on 9200 and the XWB broker on 9100. The script publishes them only when you also set PUBLISH_BROKERS=1, and then on ports Docker picks: docker port rpms-iris lists them. It also publishes the IRIS SuperServer on 11972 and the management portal on 15273, on every network interface, so run it on a machine no one else can reach. If one of those ports is already taken, set SSH_PORT, SUPERSERVER_PORT or PORTAL_PORT to a free one.

To try the IRIS path before you have a license, IRIS for Health Community Edition runs a release's RPMS database without its BMW database. Set IRIS_IMAGE=intersystems/irishealth-community:2026.2 and BMW_NONE=1, and leave out IRIS_KEY. Community Edition limits connections and database size, and its built-in license expires a year after the image was built. It is for evaluation, not for running a clinic.

Hello world: a first call from code

rpms-rpc is a Ruby client for the RPMS brokers. It needs Ruby 4.0 or later, Bundler, git, and a C compiler for one of its gems. This script signs on to the YottaDB instance from Option 1 as PROFILE,MD and prints the first page of the patient list, as a chart's patient picker reads it. Put the two files in a new directory. 

# Gemfile
source "https://rubygems.org"
gem "rpms-rpc", git: "https://github.com/lakeraven/rpms-rpc"
# hello.rb
require "rpms_rpc/cia_client"

client = RpmsRpc::CiaClient.new(host: "127.0.0.1", port: 9100)
client.connect
client.authenticate(ENV.fetch("RPMS_ACCESS_CODE"), ENV.fetch("RPMS_VERIFY_CODE"))

client.call_rpc("ORWPT LIST ALL", "", "1").first(5).each do |line|
  dfn, name = line.split("^")
  puts "#{dfn}  #{name}"
end

client.disconnect
bundle install
RPMS_ACCESS_CODE=PMD123 RPMS_VERIFY_CODE='PMD123!!' bundle exec ruby hello.rb
990051  ALPHA,AVERY
990001  ALPHA,CASEY
990027  ANCHOR,JAMIE
990050  ASHGROVE,SAM
990028  BEACON,DREW

Each line is a patient's internal number and name, from the demo clinic's synthetic patients. From here, the same client reads and writes through the RPCs RPMS registers.

What a release does not include

The Windows clients, VueCentric and BPRM, are distributed by IHS to sites and are not part of a release. A release does carry the server side they need, and its notes list what each client expects.
